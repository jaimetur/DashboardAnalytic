## Release: v0.3.3
### Release Date: 2026-09-21
#### ⚠️ Breaking Changes:
- Report Template visual configuration headers have been renamed from `Label` to `Label Position` and from `Label Color` to `Label Format`. Existing templates are read through compatibility aliases and gain the current headers when saved, but external template tooling and imports that write either former header must use the new names; `Label Format` is now a JSON list rather than a standalone colour value.

#### 🌟 New Features:
- Report Template KPIs now accept explicit `SUM`, `COUNT`, `COUNTD`, `AVERAGE`/`AVG`/`MEAN`, `MAX`, `MIN` and `MEDIAN` expressions. Cell Assistance, Chart Definition and the E2E Reporting chart viewer can compose these expressions from the selected CDR field and restore the chosen operation when reopened, while the new `Dynamic Table` chart type pivots Column Aggregation dimensions above the selected measure, preserves separate row-hierarchy fields, suppresses repeated parent labels and fits additional rows for Tableau-style validation tables. A pivot dimension repeated under Rows is treated only as a column, and tables with more than 20 distinct pivot values request a narrowing filter instead of compressing into an unreadable grid.
- Admin Import / Export / Transfer now supports multi-select content packages. Selecting a Full Workspace removes and disables its separately listed workspace elements, while Full Environment becomes exclusive because it already includes Config and every workspace selected in its confirmation dialog; combined exports and transfers are packaged as a single bundle that Import applies in order. Long selected-package descriptions remain contained within the panel and are visually truncated instead of widening the layout.
- Added configurable thematic palettes and explicit ordering for canonical Operators and Vendors. Reporting, Dashboard, Chart Builder and Dataset Analysis charts use the configured colours and order for Operator, Subscriber, Vendor and combined Operator_Vendor dimensions; Vendor colour takes precedence for combined identities, falls back to the Operator colour when no Vendor exists, and is preserved consistently across static, Canvas and CDF renders. CDF Vendor groups retain distinct solid/dashed Operator strokes, campaign recency uses line width rather than colour variants, and horizontal legends adapt their rows to prevent overlap.
- Added the Vendor Mappings manager alongside Operator Mappings, with Move Up/Move Down controls, editable aliases and colour pickers. Changes refresh only the open panel and preserve its scroll position; canonical renames migrate exact Report Template and saved-Dashboard references safely, and mappings remain portable through Import / Export / Transfer, Full Environment and Backup / Restore. Combined identities resolve the longest configured Operator prefix while exact identities such as `VF_SA` remain intact, and the former chart-specific order and colour tables are migrated into the workspace-managed component.
- Added per-chart visual configuration to Report Templates and Chart Definition: `Axis X Range`, `Axis Y Range`, `Label Position`, `Label Format`, `Exclude Null/Empty` and `Exclude Zero` now apply to every chart family. Label positions support `None`, `Top`, `Up`, `Middle` and `Down`; Label Format Cell Assistance stores an optional JSON list with hexadecimal colour, font, `Bold`/`Italic` styles and `Small`/`Medium`/`Large` relative sizes. Empty formatting retains automatic colour and normal-weight labels, and the settings work consistently in live Dashboards, static/PPT charts and hover geometry.

#### 🚀 Enhancements:
- Consolidated macOS launcher packaging into a single reproducible build script that compiles and signs the universal ARM64/x86_64 application under `macos-launcher/` and writes its installer package under `macos-installer/`, keeping both deliverables out of the project root.
- Canvas percentage charts retain compact one-decimal data labels while their hover tooltips expose two decimals for closer source-data validation.
- Dynamic Tables now start with case-insensitive alphabetical ordering at every row and pivot-column hierarchy level, invalidating older persisted and browser-cached Canvas models that retained source order. Their Canvas headers and hierarchical row members can be dragged with the mouse while retaining the associated values, with child rows and columns constrained to reordering inside their immediate parent group; progressively weighted separators now mark every hierarchy transition on both row and column axes, making first-level groups and each nested subgroup visually distinct.
- Active combined-table recreations now expose a confirmed stop action directly in their Workspace dataset row, and each running or recoverable Auto-calculated Field task exposes it beside its Materialization status progress bar. Both controls share the cooperative cancellation and live status used by the global background-task panel. Materialization cancellation is persisted outside the busy Workspace database and observed between table operations, so it also works when Stop reaches a different web worker. Stopping an incoming package transfer now uses its correct non-conflicting server endpoint and also interrupts the child materialization it launched, so `Stop all` no longer leaves either task running.
- CDF charts with more than two campaigns for the same operator now distinguish recency with progressively decreasing line widths across the four most recent campaigns, from the thickest newest curve to the thinnest oldest curve, consistently in static renders, interactive canvases and legends.
- Distribution Stacked Vertical Bars now supports declarative ordered upper-bound buckets through `Buckets < ...` and `Buckets <= ...`, generating `belowN`/`Above` categories with the Tableau throughput palette, a stable legend/stack order and larger horizontal white percentage labels inside segments large enough to contain them in both Canvas and static/PPT renders. The NSA FDTT DL and UL template rows now encode their respective `2,5,20,100` and `1,3,10,20` formulas directly instead of relying on generic numeric ranges.
- Moved the `Re-materialize auto-calculate fields` action from the Auto-calculated Fields introduction into the Materialization status header, next to its current status, so the operation sits with the progress it starts.
- Expanded the Auto-calculated Fields manager to the same wide, content-sized dialog geometry used by Dashboard editing surfaces whether opened from Workspace, the Dashboard viewer or the embedded Report Template editor, mounting the latter above its iframe so it is no longer constrained by the nested viewport. Its height now follows the actual field count without leaving an empty lower area, and the hidden editor can no longer reappear below the manager actions after closing it. The editor uses **Discard** and **Apply** to abandon or stage changes in memory, while the main list enables **Save** and **Save & Materialize** only when definitions have changed; the former persists without starting work, the latter also launches background materialization, and either closes the manager after a successful save. Adjacent up/down controls reorder definitions in memory before saving, while multi-field fallbacks and rule conditions use readable `[Field A] OR [Field B]` aliases and transparently migrate legacy `|` or unbracketed separators. Typing `[` in either source-field editor opens a prefix-filtered catalogue containing the fields available across the selected CDR types. The materialization panel now replaces its server-rendered placeholder instead of retaining it as a second progress bar, reports stopped work at its actual percentage, recognizes cross-worker stop markers immediately and advances inside each table while naming the current table, phase and completed row operations instead of remaining at 0% until that complete table finishes. Long SQLite updates are interruptible within the active statement so one Stop request does not remain indefinitely at `Stopping`, while larger bounded batches reduce transaction overhead. The manager scrolls only when needed, anchors actions at the bottom right, keeps compact controls and a flexible rules area, reloads current workspace definitions before opening, and returns to the definition list after applying or discarding so additional fields can be managed in the same session. Its Rules editor accepts both the existing ordered `condition => result` syntax and nested Tableau-style `IF / THEN / ELSEIF / ELSE / END` expressions, displays either form in the definition summary, and uses the same parsed decision tree for previews and SQLite materialization.
- CDF curves retain their complete vertical step when several samples share the automatic minimum, while exclusions remove unwanted samples before calculating the distribution; scatter exclusions cover both plotted axes. Automatic stacked-bar labels use a consistent horizontal two-decimal format throughout each chart, selecting one black or white in-bar text colour from the predominant stack colour and scaling up within bounded maxima whenever the segment or its clear lateral gap has ample space; tiny segments use the segment's own colour beside the bar and are omitted when that gap or a collision-free vertical position is unavailable, while row and column aggregation headings use a stronger bold weight. Stacked percentage and distribution charts retain every interval when applying their numeric Y domain instead of mixing proportional and pixel accumulators. Older templates remain compatible and gain empty visual-setting columns when next saved.
- Manage Dashboards now exposes editable **NR Mode** and **Template** selectors in every saved Dashboard row. A warning confirmation explains that accepting either change invalidates the Dashboard's prepared reports and charts; the dedicated update preserves its Scope, selected CDR universe, date range, adaptive and custom filters, hidden fields and comments, then queues a fresh preparation against the compatible replacement template. Renaming a Report Template updates every Dashboard that references it and replaces that template name in each matching Dashboard title before refreshing its prepared universes.

#### 🐛 Bug fixes:
- The macOS installer now disables application-bundle relocation explicitly, ensuring it installs Dashboard Analytic into `/Applications` even when another copy of the app exists inside the project.
- Applying temporary Chart Definition changes in the individual Dashboard chart editor now renders through a polled background preview job, preventing long combined-CDR queries from being cut off by a reverse proxy with an unexpected 504 response; the applied payload also repaints its chart on the parent slide when the enlarged viewer closes, while Update Template and saves from the embedded Report Template editor immediately rebuild the live Dashboard and refresh every expanded-chart and restored/PPT snapshot plus any preloaded editor, so range, label, filter and exclusion changes no longer wait for the editor to close or reopen with stale values. Label Format is preserved by temporary previews and template updates, while visual-only label colour, font, style and size changes reuse the active Canvas model instead of rebuilding the filtered CDR dataset. Explicitly closing Chart Definition now discards its unapplied draft; Apply and Update Template retain the panel and its draft, outside-click collapse preserves the in-progress values, and pointer-leave collapse waits ten seconds.
- Saving a Report Template from the Dashboard viewer and using Refresh Dashboard now invalidate the prior prepared snapshot and rebuild the template structure, so inserted, deleted or reordered slides appear immediately. Interactive template saves no longer remain behind an unbounded Workspace writer lock while CDR materialization is running; they return a clear retryable busy response after a short bounded wait. Cell Assistance also keeps the active `CDR source` cell attached while applying a suggestion, preventing the selected source from being silently discarded, and an intentionally empty Legend Position now remains empty instead of being rewritten as `Top`.
- Saving and materializing an Auto-calculated Field now records its pending rebuild atomically and updates renamed references across every Report Template and saved Dashboard before starting a single background job, avoiding the self-imposed Workspace writer lock that left the editor disabled. Large CDR updates commit bounded batches so later field-definition saves can acquire SQLite's writer between batches instead of waiting for a complete table scan. A dedicated progress dialog explains the foreground save and reference migration, then returns to the field list while the independently cancelable materialization remains visible in the background-task panel; that panel now updates its existing job rows in place instead of rebuilding them on every poll, keeps each running job percentage monotonic and uses stable numeric geometry so its bars no longer restart, jump backwards or shake. Orphaned persisted jobs expose the same stop controls and recoverable `stopped` state.
- Dashboard Filters now stays closed when a new authenticated session begins instead of restoring the Dashboard opened by a previous login in the same browser tab. Its visible/hidden and expanded/collapsed choices remain session-only, with the panel expanded by default until the user explicitly collapses it.
- Server transfers to literal private IP addresses now bypass HTTP proxy settings inherited by Docker, preventing LAN requests from being sent through an unrelated proxy. Connection failures also identify the required destination bind address, inbound port and the special `host.docker.internal` case.
- Dashboard PowerPoint generation now isolates a failed chart renderer behind a visible placeholder instead of cancelling the complete presentation, preserves its Canvas model for later inspection, and records both recoverable chart warnings and fatal export errors in App Log with the Dashboard and job identifiers.
- Dashboard Canvas rendering now locates the installed Node runtime by absolute path when launched from the macOS app, whose environment does not inherit the interactive shell `PATH`, so PowerPoint exports retain their charts instead of replacing every chart with a missing-Node placeholder.

#### 📚 Documentation:
- Documented workspace-managed Operator/Vendor ordering, thematic chart colours and the combined portable mapping component.

## Release: v0.3.2
### Release Date: 2026-09-18
#### ⚠️ Breaking Changes:

#### 🌟 New Features:
- Added a root-level macOS `Dashboard Analytic.app` launcher with the Dashboard Analytic icon and a universal native ARM64/x86_64 executable, plus a standard `.pkg` installer that places it directly in `/Applications`. Its native control window remains in the foreground while the server runs and provides Open in Browser, Restart Server and Stop Server and Quit actions instead of opening the browser automatically; restart waits for the current server to stop cleanly before launching its replacement, while closing or quitting the launcher also stops it and an independent parent-process guard prevents it from remaining orphaned after a forced application termination. The launcher reuses a working project virtual environment or creates its own native environment when existing dependencies are Intel-only, while its PID and log remain outside the app bundle.

#### 🚀 Enhancements:
- Expanded App Logs with meaningful workspace lifecycle and configuration changes plus start, completion, cancellation and failure events for scheduled/manual backups, automatic workspace reconciliation, Auto-calculated Field materialization, combined-CDR recreation, workspace duplication and Dashboard-cache cleanup. System-executed background work preserves the requesting user when available and identifies `system` as its executor.
- Chart Builder now uses the E2E Dashboard individual Canvas chart viewer directly inside the Interactive Preview panel, including its responsive renderer, semantic hover support, zoom, panning and refresh controls, instead of the embedded E2E Reporting PNG preview.
- Reprocess All and multi-file uploads now run as two explicit phases: selected Vendor Mapping datasets may process in parallel, but every CDR in the batch waits until all those mappings finish, ensuring Vendor assignment never uses a partially refreshed mapping set.
- Operator labels are no longer seeded or normalised through built-in UK aliases. Admin Operator Mappings is the sole source for reporting and dashboard label transformations; with no configured mappings, the original CDR labels remain unchanged, including in the combined table.
- Floating background-task cards now keep their workspace title, total task count, top controls and separator fixed while a vertically scrollable task list accommodates processes that exceed the available viewport height, including touch scrolling on compact screens. Tasks retain their immutable queue order oldest-first, new cards start at the top, and two-second status refreshes preserve the same scroll container and the user's current position without treating temporary layout resets as user scrolling or making the scrollbar flicker. Each workspace card also preserves its expanded or minimized state while moving between modules or reloading the page. Browser dataset uploads expose the same Interrupt task control as server jobs and retain their latest measured percentage between timer updates instead of alternating with an indeterminate progress line. Reprocessed datasets calculate queued age from the current queue transition instead of their original upload time.
- Added a configurable application-wide FIFO scheduler for background work. Config now controls the maximum simultaneous tasks (default 1); Dataset processing, mapping, reporting, exports, imports, transfers, backups and workspace maintenance all honour that shared cap, while their visible queued jobs can be stopped cooperatively before or during safe processing stages. Cancelling a backup also removes its partial ZIP and temporary snapshot data.
- Dashboard library actions now place View Dashboard before Open Filters/Close Filters with explicit text labels; compact cards keep both primary actions on one comfortably sized rectangular row, arranging each as icon plus its first word above a contained second word before the remaining icon controls.
- App Log summaries now begin with their configured-local timestamp in `[yyyy-mm-dd HH:MM:SS]` format.
- Dashboard dataset preparation tasks now remain individual entries in their workspace background-task card, with the Dashboard name included directly in each task label rather than creating Dashboard subgroups.
- Dashboard Dataset Universe counts now reuse materialized CDR row counts when complete and unfiltered; reduced (CDR/date) and filtered universes otherwise share one narrow aggregate query per combined table, with both count sets cached independently from adaptive filter catalogues.
- Config Runtime Settings now consistently lays out its Locale, Chart Rendering, Data Processing and Background Work cards in two columns on desktop.
- Opening a saved Dashboard now immediately hydrates its stored Dataset Universe and filter selections in the controls, even while background preparation is still loading the current catalogues and counts; an older browser-session universe can no longer override an explicitly saved one.
- Once an open Dashboard reaches Ready, its available chart models are warmed sequentially during browser idle time even before View Dashboard is opened, so the viewer can reuse the cached chart payloads without competing with active interaction.
- New and previously unprepared Dashboards now automatically cache four date-unrestricted universes using their saved filters, scope and template: every ready CDR of each type, the newest CDR, the two newest CDRs, and the newest plus the third-newest CDR. Every universe uses automatic `Oldest`/`Newest` dates. Manage Dashboards reports `Preparing n/4` until they are reusable while keeping **Open Filters** and **View Dashboard** enabled; an explicit open takes priority over the low-priority warm-up. Status polling now lets that background work finish instead of cancelling it between polls, so its persisted manifests are restored after restart rather than repeatedly returning to `Preparing 0/4`. Contended work reliably resumes after interactive or PowerPoint preparation. The last opened Dashboard is restored whenever E2E Dashboard is revisited or reloaded in the same signed-in browser tab, until it is explicitly closed or the user logs out.
- Ready PowerPoint Generation Jobs now provide a View Dashboard action immediately after View Charts. Its calendar-and-check SVG opens the job's immutable generated Dashboard snapshot—including its original slide layout, Canvas chart models and comments—without recalculating data or reapplying filters; Generate PPT and other mutating controls are disabled there, while View Dataset remains available and reconstructs each chart's dataset from the job's stored definition and filters.
- Generate PPT now inserts its job immediately, including for a closed or non-prewarmed Dashboard. Cache lookup, universe preparation and chart-model rendering run only after that insertion in the background worker, which first reuses a compatible persistent snapshot when one exists.
- Cold PowerPoint jobs now report progress across the real preparation (1–24%), Canvas chart-model rendering (25–90%), chart/PPT composition (91–95%) and final PPT write (96–100%) phases instead of appearing stuck at 1% until rendering ends; a chart whose stored template field is absent from a selected CDR is exported as an explanatory placeholder without failing the complete PPT job.
- Server access and execution output now uses the configured-local `[yyyy-mm-dd HH:MM:SS]` timestamp prefix and is retained in a live, scrollable Execution Log panel beneath App Logs. Production and development Docker services use the same Python launcher and logging configuration, so `docker compose logs` retains that timestamp instead of beginning at Uvicorn's `INFO:` prefix.
- Collapsed side-navigation tabs now recede into subtle edge shadows, revealing their complete Modules, Sections, Documentation or Releases handle only when the pointer approaches the corresponding viewport edge. Revealed handles and open drawers hide automatically after five seconds without pointer or keyboard focus, reset that delay on interaction and close immediately when the page scrolls or loses focus. On touch screens, tapping the left or right edge reveals the available handles for the same five-second interval before they are opened.
- Dashboard slide, Dashboard expanded-chart and E2E Reporting chart viewer First/Last navigation actions now use the same crisp line-based SVG language as the other paging controls instead of platform-dependent emoji glyphs.
- PowerPoint generation from a Dashboard library row now uses a single `Select Dashboard Datasets Universe` dialog with ordered Scope, CDR datasets and Dates sections before its Cancel and Generate PPT actions. Changing Scope refreshes the CDR checkboxes, preselecting the two newest datasets of each type for Operator Comparison or the newest one for Multivendor Comparison; Dates initially reflects that Dashboard's saved concrete or automatic Oldest/Newest range, and the export preserves the complete explicit universe. On compact screens, bounded per-type CDR lists, two-column date controls and correctly sized fields keep the panel within the viewport, its central content independently scrollable and its actions always visible.
- View Dashboard from the Dashboard library now opens the viewer without expanding the main filter panel. Viewer and individual-chart actions consistently call it Dashboard Filters, and its floating panel omits the redundant View Dashboard and Generate PPT controls. The main Dashboard Filters panel starts collapsed for every new authenticated session, while its open or closed state survives reloads and module navigation only within that same session. Discarding applied but unsaved filters or Dataset Universe changes while leaving restores their saved values, including the session-retained universe, and filter preparation retries one transient proxy 501 response. Every action in the viewer's upper row combines an SVG icon with text at a consistent size; the orange Generate PPT action appears immediately before the red Refresh Dashboard action at the end. Presentation now leads the slide-navigation row and is separated from First by a spaced vertical divider, while presentation mode retains separate floating Pause/Resume and Stop controls.
- PowerPoint Generation Jobs and Charts Panel now rely on the E2E Dashboard stack's single consistent inter-panel gap instead of adding their own top margins; the movable Dashboard Filters host also disappears from the grid while its panel is hidden or floating, preventing an empty row from creating extra whitespace.
- Selecting Full Environment in Admin Import / Export / Transfer no longer opens the workspace picker immediately. The picker now appears only after pressing Export ZIP or Transfer to other server, and each action requests its own current workspace selection before it starts.
- The release utility is now `CreateUpdateRelease.py`, with separate Update Current Release and Create New Release actions. It can create a version-named local branch after confirming how to handle pending work, add an empty dated changelog release, update application metadata, commit the result and publish the new branch to `origin` automatically.

#### 🐛 Bug fixes:
- App Logs now renders timestamps and derives date filters with the timezone selected in Application Runtime instead of relying on the host process timezone, preventing UTC offsets and midnight events from appearing under the wrong local date.
- CDR processing with explicitly selected Vendor Mappings now fails visibly when mapping raises an error or leaves any Vendor value empty, instead of publishing an apparently successful Ready dataset without complete mapped Vendors.
- The Dashboard viewer now uses compact layouts on small screens: landscape reduces its header and uses single-row selection/actions plus a combined tool/navigation row, while portrait also combines playback/navigation without clipping, compacts editing controls and expands the proportionally positioned chart composition through all remaining viewport height instead of stacking oversized fixed-height charts or leaving unused space. Its collapsible Comments drawer stays fixed to the visible bottom edge and device safe area in landscape independently of overflowing slide content, instead of appearing in the middle of the viewer. The Presentation settings dialog is constrained to the visible viewport, scrolls vertically with touch momentum and keeps its header and actions reachable. Across compact modules, Collapse/Expand stays on the title row at the right, and Charts Panel uses a smaller chart-count badge that does not overlap its title.
- Configuration and Full Environment imports now preserve destination-local server-transfer handshakes while replacing the application database, preventing transfer status polling from briefly returning Not Found and aborting an otherwise successful incoming import.
