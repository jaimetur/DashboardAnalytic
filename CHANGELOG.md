## Release: v0.3.0
### Release Date: 2026-09-14
#### ⚠️ Breaking Changes:
- Renamed former `E2E Dashboard` module to `Datasets Analysis`, including its controls, internal analysis references and canonical `/datasets-analysis` routes; legacy `/dashboard` routes remain available as compatibility aliases. Help chapters now place E2E Dashboards immediately before E2E Reporting.
- Renamed the E2E Reporting page, API, generated report, Chart Set and job routes to the canonical `/e2e-reporting` and `/api/e2e-reporting` prefixes. Legacy `/reporting` links redirect to the new location.

#### 🌟 New Features:
- Added E2E Dashboards with workspace-persisted Dashboards, create/open/save/close/duplicate/delete and JSON import/export, all workspace templates, combined CDR selections, adaptive date/dimension filters and custom Auto-calculated Field value filters. Its large viewer groups all charts by Slide using template Layout positions, with navigation, synchronized floating filters, filtered chart datasets with cached partial-row pagination, compact CSV download icons, template editing and the shared Auto-calculated Field manager.
- Added persistent per-slide Dashboard comments with editable bullet-style notes in an independently scrolling area placed below the charts or at their right according to the selected Layout, plus Presentation mode with selectable 3/5/10/15-second automatic transitions and Fade, Slide or no effect.

#### 🚀 Enhancements:
- Reused shared materialized CDR tables and Reporting chart preparation for Dashboards, with consistent filtered snapshots, debounced changes and stale-response protection. Dashboard preparation now calculates exact filtered row counts and filter catalogues for every selection; small selections retain indexed row keys, while large selections use direct SQL predicates without copying their complete CDRs. A bounded, revision-keyed analytical SQLite cache stores only the fields required by each Dashboard/template, is built when Dashboard preparation needs it and is rebuilt only when its datasets or required columns change, so management operations never wait for large projection copies. Each live chart reads its minimal filtered projection and returns a compact JSON model with bounded CDF/scatter samples or pre-aggregated bars/tables. The browser paints it from a 1600 × 900 logical canvas using the historical Report/Chart Set renderer's row/column hierarchy, aggregation and campaign ordering, Operator/Vendor/Campaign palettes, titles, legend content and position, line emphasis and semantic hover values; Map charts also share its OpenStreetMap viewport and load tiles asynchronously. Reports, Chart Sets and previews now use that Canvas painter by default, share Dashboard-style filtered frames and persist its in-paint semantic hits instead of recalculating tooltip geometry in Python; the legacy PIL painter remains available through `DASHBOARD_ANALYTIC_REPORT_CHART_RENDERER=pil`. The renderer stretches each chart independently to fill its complete template placeholder, centres its visible Rendering state and supports independent 100–400% chart zoom with drag-to-pan; Title and Transition dashboards use large typography plus the Dashboard Analytic logo and title. Exact chart models persist across restarts; saved Dashboards warm every Canvas model through a bounded server queue, and opening View Dashboard waits for any missing models before showing the viewer, so its charts load immediately. Repeated charts share their filtered frame. Docker multi-platform builds keep their large Chromium dependency cache in Docker Hub and cancel superseded duplicate builds; tag releases invoke this workflow only through Build All, avoiding repeated ARM64 emulation. Added incremental shared-CDR column backfills, deterministic invalidation, a distinct muted-violet theme, responsive template layouts, and a pastel-yellow preparation notice that turns pastel green when View Dashboard is available.
