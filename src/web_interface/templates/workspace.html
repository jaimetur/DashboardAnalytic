Vendor mapping rule · Network Inventory
  1. For each CDR sample, split Cell_ID_A (or an equivalent Global Cell ID field) in chronological order and retain only the first and last Global Cell ID.
  2. Look up both endpoints in the selected mapping:
    • VFUK for every Vodafone Operator (any name starting with Vodafone or VF);
    • 3UK for every Three Operator (any name starting with Three or 3).

Vodafone UK and Three UK: every Vodafone and Three Operator is mapped, and <Operator> is:

  • Vodafone for Vodafone, Vodafone UK, VF or VFUK (for example Vodafone_Ericsson);
  • 3 for 3, 3UK, Three or Three UK (for example 3_Ericsson);
  • the Operator's own name for any other Vodafone or Three Operator, such as tests in another mode (for example Vodafone SA_Ericsson, Vodafone VoNR_Ericsson or VF_SA_Ericsson).

Result:

  • The same non-empty Vendor at both endpoints returns <Operator>_<Vendor>.
  • If Ericsson is present at either endpoint and the other Vendor is different or missing, the result is <Operator>_Ericsson (Mixed).
  • Every other different or missing endpoint combination returns <Operator>_Mixed (non-Ericsson).

Network Inventories of any other Operator follow the same rule with the cells of their Operator (a global cell ID, or eNodeB/gNodeB ID with local cell ID, and a Vendor column).

Operators without an inventory (for example O2 and EE, or Vodafone and Three without a selected mapping): no Vendor is assigned; the result is <Operator> - All.

The mapping populates the columns Vendor, Operator_Vendor and Vendor_Operator according to this rule.

Vendor mapping rule · Vendor polygons
  1. Each selected Vendors — Geospatial dataset belongs to the Operator chosen for it or, when Multi-operator, gives each polygon the Operator of its Operator attribute.
  2. For each CDR sample, find the polygon of its own Operator that contains its start position and the one that contains its end position (Call_End_Latitude_A/Call_End_Longitude_A in Voice CDRs; Data and Speech CDRs only record the start, which is then also the end).

Result, for every Operator with Vendor polygons:

  • The same Vendor at both positions returns <Operator>_<Vendor>.
  • If Ericsson is at either position and the other Vendor is different or missing, the result is <Operator>_Ericsson (Mixed).
  • Every other different or missing combination returns <Operator>_Mixed (non-Ericsson).
  • A sample outside every polygon of its Operator, or without coordinates, returns <Operator>_Unknown (Vendor Unknown).

Operators without Vendor polygons: no Vendor is assigned; the result is <Operator> - All.

The mapping populates the columns Vendor, Operator_Vendor and Vendor_Operator according to this rule.

Region mapping rule
  1. The selected GeoJSON or Shapefile provides the Region polygons and their Region or WP labels.
  2. For each CDR sample with usable latitude and longitude, the mapping assigns the label of the polygon that contains its coordinates.

Existing non-empty Region values are retained. Samples without valid coordinates, or outside every mapped polygon, remain unchanged.

Cluster mapping rule

The selected Clusters — Geospatial polygons assign their Cluster label to the Cluster column of every CDR sample whose coordinates fall inside a polygon, in the same way as Regions. Existing non-empty Cluster values from the source CDR are retained.
